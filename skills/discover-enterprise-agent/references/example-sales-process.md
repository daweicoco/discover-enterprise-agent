# 示例：MTC 前半段销售决策助理

此示例由某新能源企业的销售流程抽象而来，仅用于展示方法，不得机械套用到其他企业。

## 一、已确认边界

- 服务对象：区域一线销售。
- 覆盖范围：管理市场、管理线索、管理商机、谈判与合同签署。
- 核心使命：帮助销售更早发现有效机会、更快判断商机、更有证据地准备竞争策略并证明客户价值。
- 明确排除：合同执行、订单状态 BI、排产、库存、物流、财务及售后服务。
- Public Tender 与商机资格初判属于连续链路，但不是同一任务。
- 电价预测和 ROI 快速测算是跨“管理商机—谈判与合同签署”的价值证明能力，不是独立顶层流程。

## 二、从哪来

| MTC 关键流程 | 核心输出 | 对应能力 |
|---|---|---|
| 管理市场 | 与目标国家、客户和产品方向相关的市场机会清单 | 公开 Tender 持续发现、市场信息采集、机会识别、基础匹配 |
| 管理线索 | 可信、结构化、可分派的销售机会卡 | Tender 信息抽取、来源追溯、线索去重、客户/项目识别、线索初步筛选 |
| 管理商机 | 商机判断摘要、优先级建议、信息缺口及下一步准备清单 | 商机资格初判、客户与项目背景补充、产品适配判断、竞争态势识别、电价与市场条件分析、ROI 快速测算 |
| 谈判与合同签署 | Sales Brief、竞争打法、客户异议应对和客户价值证明材料 | Competing Book 证据检索、产品与竞品对比、竞争策略生成、客户沟通准备、ROI 结果解释和价值摘要生成 |

## 三、为什么暂不拆分

Public Tender、Competing Book、ROI 快速测算共同支持一条连续责任循环：

```text
发现机会 → 判断机会 → 准备竞争策略 → 证明客户价值 → 支持销售决定下一步
```

它们服务同一主要用户、围绕同一商机对象、由同一销售决策消费，因此可保留为“销售决策助理”的能力组。

订单状态 BI 不进入该角色。它主要服务销售运营，围绕订单执行对象，触发节奏、数据、协同对象和责任闭环均不同；若未来建设，应作为独立的销售运营/订单执行角色评估。

## 四、一期最小闭环

| 项目 | 建议 |
|---|---|
| 真实任务 | 选择一条真实 Tender 及对应商机 |
| 核心链路 | 机会发现—资格初判—竞争准备—ROI/客户价值证明 |
| 核心能力 | Public Tender、Competing Book、ROI 快速测算 |
| 目标成熟度 | 以“可信数据＋来源”为主，部分能力结合具体商机提出建议 |
| 人工检查点 | 销售确认是否跟进、竞争打法和所有对外承诺；专业人员确认模型和关键假设 |
| 本期不做 | 订单 BI、自动投标、自动报价、自动审批、自动客户承诺 |
| 专业力 | 系统、数据、模型、算力和安全维度先保留标题，统一写“待评估” |
