# 决策层—管理层—执行层 Agent 角色家族

仅在用户需要覆盖端到端流程、多个组织层级或 Agent 组合关系时使用。不要因为企业存在三个管理层级，就机械生成三个 Agent。

## 一、三层定义

| 层级 | 主要任务 | 典型输入 | 核心输出 | 人机关系 |
|---|---|---|---|---|
| 决策层 | 判断方向、情景与资源取舍 | 外部趋势、经营目标、组合表现、重大风险 | 情景判断、战略选项、资源配置建议、重大决策材料 | AI 提供证据与选项；决策者承担最终取舍 |
| 管理层 | 监控目标、解释偏差、协调跨团队行动 | 计划、过程指标、异常、预测、资源状态 | 组合看板、偏差诊断、优先级、协调与升级建议 | AI 归纳和预警；管理者分配资源并推动闭环 |
| 执行层 | 完成边界清晰的流程任务 | 业务单据、规则、知识、上下文 | 结构化结果、草稿、核验、提醒或经授权的系统动作 | AI 执行或辅助；高风险动作保留审核 |

## 二、从流程生成角色家族

1. 沿端到端流程标出每一层真正需要回答的问题。
2. 将相同使命、业务对象、责任循环和节奏的问题聚成一个候选角色。
3. 标出共享能力服务，例如检索、预测、计算、文档生成；共享能力不必单独人格化。
4. 识别角色之间的输入输出契约，而不是只画组织汇报关系。
5. 用真实任务验证每个候选角色；没有独立结果和责任循环的候选项降级为能力。

## 三、拆分与合并

可保持同一个 Agent 的情况：

- 服务同一角色，围绕同一业务对象形成连续闭环；
- 输出共同支持同一个业务决定；
- 工作节奏、权限和风险大体一致；
- 切分后会增加上下文丢失或重复操作。

应考虑拆分的情况：

- 一个角色服务销售做机会判断，另一个服务销售运营跟踪订单执行；
- 一个角色提供跨区域资源取舍，另一个负责单据级任务执行；
- 一个角色只读分析，另一个可写入系统或对外承诺；
- 两部分由不同责任人验收，且各自有独立闭环。

## 五、完整性检查

- 每个 Agent 是否有独立且稳定的使命？
- 是否有明确的人类服务对象和结果消费者？
- 是否基于真实流程，而不是组织名称或技术平台？
- 角色之间是否通过业务产物衔接？
- 是否存在重复采集、重复判断或相互矛盾的建议？
- 共享能力是否被误当成独立 Agent？
- 自主程度是否与风险和责任匹配？
