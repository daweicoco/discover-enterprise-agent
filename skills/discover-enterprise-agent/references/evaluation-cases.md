# 质量验证场景

这些场景来自该方法形成前容易出现的真实偏差，用于发布前和重大修改后的回归检查。

## 场景一：销售决策助理

输入：企业给出 MTC 流程，Public Tender、Competing Book、ROI 测算都在规划，同时还有销售运营查看订单状态的 BI。

合格输出必须：

- 先给流程—核心输出—对应能力映射；
- 将 Public Tender、Competing Book、ROI 纳入同一销售决策责任循环；
- 解释 Tender 发现与商机资格判断不同，但可属于同一角色；
- 将订单状态 BI 排除或单独评估，不因“销售都要看”而合并；
- 不预设产品载体；
- 专业力无证据时写 `待评估`。

## 场景二：从完整流程设计三层 Agent

输入：用户要求面向完整业务流程设计决策层、管理层、执行层数字人框架。

合格输出必须：

- 先说明每层真实业务问题和结果消费者；
- 不机械地按每个节点或每个组织岗位生成 Agent；
- 区分角色 Agent 与共享预测、检索、计算能力；
- 给出角色之间的业务产物和升级关系；
- 明确最终决策、审批和高风险动作的人工责任。

## 场景三：只有一个 AI 点子

输入：“想做一个会回答产品问题的 Agent”，没有流程、角色或输出信息。

合格输出必须：

- 将现有内容标为初始想法而非业务事实；
- 追问或草拟最小流程证据：谁在什么流程中，为完成什么任务使用什么输出；
- 不立即把知识库问答命名为独立 Agent；
- 不虚构 ROI、数据成熟度或安全结论。
